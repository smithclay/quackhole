      Connect to this DuckDB?

      This link points at a DuckDB someone is running. Attaching it lets this tab query that machine directly, over an encrypted relay.

      Machine

      Relay
      —
      • Nothing is installed. DuckDB is WebAssembly running on this page. The session lives in this tab, and closing it ends everything in it.
      • That machine gets no access to this one. This tab dials out and reads the answers back. It hands over no files and opens nothing for them to connect to; what comes back is query results, parsed inside the browser's sandbox.
      • The relay only carries ciphertext. Traffic is encrypted end to end between this tab and that machine. The relay sees two endpoint ids, the timing and the byte counts — not your SQL, and not the results.
      • Treat this full link like a password. The access token is part of it and does not expire. Anyone you pass it on to can query that machine until whoever runs it stops serving — so keep it out of chats, issues and commits, and connect only if you trust who sent it to you.

      Start DuckDB on a VM, sandbox, or laptop

      Start DuckDB somewhere with the quackhole extension. Whichever way you start it, it prints a ticket which connects this browser tab to it.

      Hand this to the agent that has access to DuckDB (it's a small binary that runs everywhere).

      It sends the agent to llms.txt — this project's docs written for one — rather than spelling the steps out, so it installs the signed extension instead of guessing at flags. Read it yourself if you would rather know what you are asking for.

      For a DuckDB you already have open. quackhole_serve waits for the endpoint to learn its home relay and returns the link to open.
