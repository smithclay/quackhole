      What is actually happening

      The address is a public key

      quack:<endpoint-id>.iroh:9494. That is a 32-byte ed25519 public key in z-base-32 — 52 characters, so it fits a DNS label. Nothing resolves it; quackhole intercepts before a socket exists. Connecting to the right address and authenticating the server are the same operation, so there is no certificate to issue, renew or trust.

      Quack is still the protocol

      quackhole is a transport bridge and nothing else. Quack stays the database protocol; its HTTP rides iroh QUIC streams, which supply identity, NAT traversal, relay fallback and encryption. The machine you query cannot tell this tab apart from a native DuckDB.

      A browser can only relay

      iroh compiles its IP transport out entirely under cfg(wasm_browser), because a browser cannot open a UDP socket. There is no hole punching and no direct path from here — ever. Traffic stays end-to-end encrypted; the relay forwards ciphertext it cannot read. Between two native peers, a direct path is possible.

      The bridge under this tab

      DuckDB-Wasm's Quack client makes synchronous XHR calls from a worker, so the transport has to block. This page replaces XMLHttpRequest inside that worker and parks it in Atomics.wait on a SharedArrayBuffer while a second worker does the async iroh work — which is why the page needs cross-origin isolation.
